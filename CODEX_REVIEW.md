# Antigravity follow-up: targeted fixes before release

Codex inspected the current source and `ANTIGRAVITY_RESULTS.md`. This is a targeted static review, not an independent rerun of the reported tests. Continue from the existing code. Do not deploy yet.

1. **Mapped syllabus coverage must save successfully, not merely display.** The Android editor now offers topics from mapped shared syllabi, but backend `applyChanges` collects coverage IDs from the destination workspace's syllabus records and proposed syllabus changes. A private assessment selecting shared topics can therefore fail with `Coverage contains unknown topics`. Resolve authorized mapped syllabus references on the server, enforcing current group membership and enrollment. Add a callable integration test that saves a private assessment against a mapped shared syllabus and rejects the equivalent request after membership removal. Test both supported mapping/enrollment forms.

2. **Conflict recovery must apply the exact local version reviewed.** `resolveConflict` checks the reviewed server revision but fetches the latest local record after the review. It then removes all pending single-record edits to that ID. Pass the reviewed local revision/payload identity and compare it inside the Room transaction before acknowledging or replacing anything. A concurrent local edit must reopen review and survive intact. Add a database/repository test for this race.

3. **Outbox isolation needs dependency-aware tests.** `retryPending` continues after terminal errors but still stops all work on revision conflicts, while failed entries remain eligible every periodic retry. Block dependent writes for a failed record/course; allow independent work to proceed. Give terminal items an explicit repair/discard path and avoid endlessly resending them unchanged. Test an invalid course followed by its dependent assessment plus an unrelated valid message, and a conflicted record followed by unrelated work. Preserve idempotency and local data.

4. **Verify the actual backend suites and correct documentation.** `npm test` runs seven domain unit tests only. Run `npm.cmd run test:rules` and, separately, `$env:FUNCTIONS_DISCOVERY_TIMEOUT='60'; npm.cmd run test:integration` against `demo-acn-planner`. The current report's statement that keys are never sent to the backend is incorrect: the approved design sends the key transiently to the authenticated relay. State encrypted device storage, transient relay transmission, and no server persistence/logging. Do not claim a clean working tree or all tests passing without checking.

Prefer tests of production helpers/repositories over copying UI expressions into test bodies. The current dropdown and coverage tests repeat implementation expressions and do not prove the UI-to-backend workflow.

After fixing these items, run Android unit/build/instrumented checks as appropriate and all three backend suites. Update `ANTIGRAVITY_RESULTS.md` with exact results and remaining gaps from `ANTIGRAVITY_HANDOFF.md`. The full approved plan is not complete merely because these checks pass. Keep production deployment and live portal/Gemini verification explicitly separate.
